烟花
Spine

发布于 1970/01/01 | 约0字

假设观察者能访问一个与目标程序共享的内存页。目标程序根据内部状态读取其中某一条缓存行；观察者先把这条线从缓存中移出，留出一段时间，再读取并计时。若重载很快，说明这条线在等待期间重新变得容易访问。这个结果是一次缓存观测。它还不能单独说明是谁访问了这条线、为什么访问，更不能直接给出内部状态的值。

计时与性能计数器讲怎样界定测量窗口。本节继续追问：当读数变短时，证据链究竟走到了哪一步？例子采用 FLUSH+RELOAD 的单行探测。读者需要把每一步对应到缓存行、共享映射、处理器指令和观察者读数。

先确定被观察的是哪一条缓存行 ​

内存页是操作系统映射内存时使用的单位；缓存以缓存行为传送和保存数据。两个进程的虚拟地址可以不同，但若它们的页表项最终指向同一物理页，那么页内相同偏移处就是同一物理地址，也就对应同一条缓存行。

设目标程序把某个只读共享页映射在虚拟地址 V，观察者把同一物理页映射在虚拟地址 S。两边的地址数值不必相等。若观察者关注页内偏移 0x240，它测的是 S + 0x240 所在的整条缓存行；目标程序访问 V + 0x240 时，实际触及的是同一物理缓存行。

进程本进程的虚拟地址页表映射后的物理位置
目标程序V + 0x240P + 0x240，缓存行 L
观察者S + 0x240P + 0x240，同一缓存行 L

表中 V 和 S 属于各自进程的虚拟地址空间，P 表示相同的物理页。两个进程不能因此互相读取对方的虚拟地址；它们只是通过各自的页表映射访问同一物理位置。共享库、只读文件映射或虚拟机的去重页都可能形成共享映射，能否共享要由操作系统与运行环境决定。FLUSH+RELOAD 论文利用了共享页，并在其测试平台上观察到目标与探测程序可以运行在不同核心。这个条件不应泛化成“所有机器、所有缓存层都能跨核共享同一种状态”。

为了把观察过程写清楚，令目标程序的内部状态为 q，它选择是否读取缓存行 L：

c
/* shared_line 指向共享页中的 L；q 是目标程序已经得到的状态。 */
static volatile uint8_t sink;

static void victim_access(volatile const uint8_t *shared_line, uint8_t q)
{
    if (q)
        sink ^= shared_line[0];
}

这段代码只给出一种可能的依赖关系。若 q 为真，目标执行到 shared_line[0] 的加载，L 可能因此进入缓存层次；若 q 为假，程序不执行这次加载。sink 让这次加载的结果继续影响程序状态，避免示意代码中的读取成为无用操作。实际程序还可能有编译器改写、其他控制流、预取和投机访问，所以源码中的 if 不能直接当作硬件轨迹。分析真实程序时，应查看编译后的指令和目标地址，再判断访问是否会落在 L。

目标加载完成后，数据可能留在目标核心的私有缓存，也可能处于共享缓存或一致性协议可提供的位置。观察者随后重载时，实际数据来源取决于缓存层次、包含关系和一致性实现。因而“重载较快”不能直接翻译成“目标把数据放进了 L3”；它首先表示本次加载的服务路径比校准样本中的慢路径更短。要判断具体命中了哪一级，还需要额外的计数器或处理器文档证据。

一轮探测怎样留下读数 ​

FLUSH+RELOAD 一轮由三个阶段组成。先刷新目标缓存行，再给目标一段执行时间，最后重载同一缓存行并测量用时。

阶段观察者做什么若目标访问了 L若目标没有访问 L
Flush对 S + 0x240 执行 CLFLUSH此时尚未发生本轮目标访问同左
Wait暂停探测，让目标运行目标加载可能使 L 在缓存层次中重新可用L 通常仍需从较远层级取得
Reload读取 S + 0x240 并计时可能较快完成通常较慢完成

CLFLUSH 的操作对象是地址所在的整条缓存行，不是某个 C 变量的单独字节。Intel 手册规定，支持该指令的处理器会在缓存一致性域中使这条线失效；若某级缓存持有修改过的数据，还要先写回。它不等于“把数据从 DRAM 擦除”，也不等于把其他进程的数据权限改掉。刷新后，程序仍可正常加载这个地址，只是后续访问需要重新取得该缓存行。

这三个阶段的先后关系很重要。若加载与 CLFLUSH 次序不明，观测者可能把自己刚才的读取当成目标访问；若两个进程没有共享物理页，目标访问另一份副本不会使观察者的那条线变热；若等待过短，目标访问可能与 Reload 重叠，读数就不再表示清楚的“等待期间是否访问”。

时序也不是只由 Flush 和 Reload 决定。以下是三种不同轨迹：

轨迹时间顺序可能的重载结果对本轮解释的影响
没有目标访问Flush → Wait → Reload较慢与“等待期间无人重新取得该线”相符
目标先访问Flush → 目标加载 L → Reload较快与“等待期间有访问使该线变热”相符
目标访问与 Reload 重叠Flush → Reload 开始 → 目标加载 L结果依赖两次加载谁先取得数据可能漏记目标访问，时间槽的边界不再清楚

第三种情况不是靠“再测一次”就能自动消失。论文讨论了探测与目标访问重叠造成漏测的情形：观察者可能已经发起自己的加载，目标随后复用这条线，于是该目标访问没有形成一轮独立的缓存填充。等待时间加长可以减少这种重叠的机会，但会降低时间分辨率；应根据目标操作的持续时间和探测间隔设计时间槽。

用 C 校准本机的两种读数 ​

在解释目标程序之前，先确认测量代码能否区分本机上的“刚读过”和“刚刷新”两种状态。下面的完整程序只访问本进程中的公开字节：先制造热缓存状态，再刷新同一条缓存行，随后读取并打印时间戳差。它用于检查计时窗口和读数分布，不模拟跨进程共享，也不从内部状态恢复数据。

c
/* cache_probe_calibration.c
 * GCC/Clang，x86-64。输出 TSC ticks，不把它直接称为核心周期数。
 */
#include <stdint.h>
#include <stdio.h>
#include <x86intrin.h>

_Alignas(64) static volatile uint8_t probe_line[64] = {0x5a};

static inline uint64_t read_tsc_ordered(void)
{
    uint32_t low, high;
    __asm__ volatile(
        "lfence\n\t"
        "rdtsc\n\t"
        "lfence\n\t"
        : "=a"(low), "=d"(high)
        :
        : "memory");
    return ((uint64_t)high << 32) | low;
}

static uint64_t time_one_load(void)
{
    uint64_t begin = read_tsc_ordered();
    uint8_t value = probe_line[0];
    uint64_t end = read_tsc_ordered();
    (void)value;
    return end - begin;
}

int main(void)
{
    for (unsigned int i = 0; i < 40; ++i) {
        uint8_t value = probe_line[0];
        (void)value;
        printf("warm,%llu\n", (unsigned long long)time_one_load());

        _mm_clflush((const void *)&probe_line[0]);
        _mm_mfence();
        printf("flushed,%llu\n", (unsigned long long)time_one_load());
    }
    return 0;
}

read_tsc_ordered 通过 LFENCE 把时间戳读取与周围指令隔开；time_one_load 只包住对 probe_line[0] 的一次易失加载。volatile 要求编译器保留这次 C 级访问，内联汇编的 memory clobber 则阻止编译器把内存访问跨过时间戳边界移动。CLFLUSH 之后的 MFENCE 让刷新与后续访问按代码预期排序。代码每轮先读热状态，再刷新并读冷状态，适合确认两种情况是否有可辨认的差异；用于正式实验时，还应交错或随机化状态顺序，收集足够多的样本，并报告分位数和异常值，而不是只打印单次结果。

输出中的数值包括时间戳和栅栏本身的开销。TSC ticks 也不必等于当前核心的一个时钟周期。先看两类读数的整体分布，再判断它们是否分开；不要把某次运行得到的某个数字抄成通用阈值。论文中的阈值是为特定处理器、操作系统和计时实现校准出来的，作者明确指出不同平台的缓存延迟和虚拟机噪声会改变读数。

FLUSH+RELOAD 论文提供了一个有明确平台条件的校准例子：作者在运行 CentOS 6.5 的 HP Elite 8300、Core i5-3470 上测量 100,000 次。论文报告的 L1 读数约为 44 cycles，内存读取数中超过 98% 落在 270 至 290 cycles；L1 的 44 cycles 包含 RDTSC 和栅栏的测量开销。结合目标访问 LLC 时的预期延迟，作者在该系统上选用 120 cycles 作为阈值。换到另一台 Xeon E5-2430 或 KVM 虚拟机，加载延迟和长尾噪声都不同。这个结果的价值在于展示“先校准、再定阈值”的方法，不在于提供一个可照抄的数字。

本机校准只回答“这段程序能否区分我主动制造的两种缓存状态”。它没有回答“目标程序是否访问过同一个物理缓存行”。要把探测结果归因给目标，还要证明共享映射、目标与探测的时间关系，并排除其他会访问该行的执行者。若线程可能迁移，还要检查两次时间戳是否来自不同逻辑处理器；可以固定线程亲和性，或使用处理器支持的时间戳辅助信息检查迁移。TSC ticks 是时间戳计数，不应不加说明地当作核心时钟周期。

阈值怎样变成证据 ​

若两类读数形成分布，可选择阈值 T：小于 T 记为“较快”，大于或等于 T 记为“较慢”。阈值是分类规则，不是处理器对“命中”的定义。应当用已知状态的校准样本检查它会把多少次热缓存判慢、又把多少次刷新后的访问判快。

下面是教学数据，不是某台机器的实测结果。已知访问组共 200 次，已知未访问组共 1,000 次；目标状态由实验安排预先知道：

已知状态读数判为较快读数判为较慢合计
目标在等待期间访问过18317200
目标没有访问239771,000

在这些数据里，“较快”有 206 次，其中 183 次对应已知访问；有访问的 200 次中，17 次被判慢。于是阈值产生了假阳性和漏测。表中的“较快判定可信度”是 183 / (183 + 23) ≈ 88.8%；“访问检出率”是 183 / (183 + 17) = 91.5%。这两个比值回答不同问题：前者问一个快读数有多大比例对应真实访问，后者问已知访问有多大比例被测出来。部署条件改变后，二者都要重新测。单轮较快读数不能被翻译成“目标一定访问”；多轮统计也要连同假阳性率、漏测率和样本条件一起报告。

若两个分布大量重叠，调一个阈值不能创造原本没有的区分能力。应先检查测量窗口、核心迁移、抢占、同线其他访问、预取以及计时器精度，再决定该测量是否足以回答问题。对多个采样点做中位数或投票能抑制部分偶发噪声，却不能补上缺失的共享条件或错误的因果解释。

从“较快”到安全结论还差哪些步骤 ​

一次较快的 Reload 至多支持一个有限判断：在给定平台、计时窗口和干扰条件下，观察者读取 L 的代价较小。若刷新后目标访问是唯一能够使 L 重新可用的动作，这个读数才支持“目标在等待窗口内访问过 L”。现实中还要考虑以下替代解释：

  • 目标以外的线程读取了同一缓存行。缓存按整行传输，相邻变量或代码也可能与被观察地址处于同一行。
  • 硬件预取器或处理器的投机访问提前取得了这条线。FLUSH+RELOAD 原论文把预取和投机访问列为可能造成误报的因素；刷新也不保证该线在之后一直不被重新取入。
  • 目标访问与探测重叠，或线程被调度到不同核心，改变了测量时间槽与目标操作的对应关系。
  • 目标确实访问了该行，但源码中的访问路径与编译后指令不同，或访问与秘密状态之间并无唯一对应关系。

因此，证据链应逐层陈述：先确认计时程序测到一次加载的延迟；再用已知状态说明阈值如何区分类别；随后确认被测地址与目标地址是否共享物理缓存行、目标活动是否落在该时间窗；最后才分析这条访存是否依赖受保护数据。只有最后几步也有证据，才能把缓存活动与某种内部状态联系起来。要进一步声称恢复了秘密，还必须展示从多次观测到候选值的解码过程，并用已知输入验证结果。

这也解释了为何性能计数器不能替代攻击者视角的计时。计数器可以显示某个执行阶段出现了缓存未命中，却不自动证明另一进程能读取这个状态；探测者自己的计时则显示外部观察到的差异，却不自动说明差异由哪个内部事件产生。两种证据可以互相补充，测量窗口和观察者权限仍须分别写明。

在 Spectre v1 的 PoC中，瞬态路径读取一个字节，再用 array2[value * 512] 访问候选探测行；随后程序逐行计时，判断哪一行更容易读取。这里的候选数组位于同一进程中，因此它展示的是“瞬态访问怎样把值编码到缓存，再由计时恢复”的完整链条，并不检验跨进程共享页条件。FLUSH+RELOAD 则把探测对象换成目标与观察者共同映射的物理缓存行。两种场景都要把“哪条线变快”与“为什么这条线变快”分开论证。

练习：只改变探测间隔

原来每 2,500 个 TSC ticks 探测一次。现在目标对同一条线的访问窗口可能持续 4,000 ticks，其余条件不变。观察者每轮仍然只在时间槽末尾 Reload。哪些目标访问可能被漏掉？把间隔改成 1,000 ticks 后，时间定位能力发生了什么变化，又为什么这仍不能单独排除预取造成的较快读数？

较长的访问窗口可能跨过原来的探测点，或与 Reload 重叠，因此观测到的点不再唯一对应目标开始访问的时刻。缩短间隔会增加采样点、改善时间定位，但不会建立“只有目标能取得该行”的前提；预取或其他线程仍可能使 Reload 变快。判断仍需比较已知访问与已知不访问的校准分布，并核对共享关系和目标代码。
