共享缓存一节里，A 原本能反复使用自己的三个块。B 加入后，它们却在同一组里轮流被换出。如果让 B 只能在第四路填入新块，A 还能留下几块？将 A 从全路组移到三路组之后，已经在第四路里的旧块又会怎样？两道题都用到 Intel CAT（Cache Allocation Technology，缓存分配技术），答案取决于掩码在哪个环节被查阅。

任务所在组怎样影响一次缓存填充 ​

一条加载到达末级缓存（LLC）时，地址的组索引和标记决定查找哪个组、是否已有所需块。若需要填入新块，还要从本组选一个位置。CAT 为这个选择加上限制。缓存可从请求所属的服务等级查到掩码，在掩码允许的位置中选空路或替换候选。

结构保存什么什么时候使用
服务等级（CLOS）任务请求所属的分配类别，用 CLOSID 编号确定该按哪一份资源配置进行分配
IA32_PQR_ASSOC当前逻辑 CPU 的 CLOSID 和资源监测编号 RMID在 Linux x86 的任务调度路径上按需更新
L3 容量掩码（CBM）当前 L3 分配域中每个 CLOS 对应的可分配位置请求需要新分配时，用 CLOSID 取得相应掩码
缓存组各路的标记、有效状态、数据与替换状态查找已有块。需要填充时，再在掩码允许的路中作选择

在支持 L3 CAT 的 Intel 处理器上，L3 掩码由 IA32_L3_MASK_n 这一组寄存器配置，下标 n 对应 CLOSID。Linux resctrl 把配置写成每个控制组的 schemata。因此要知道一次填充可以去哪里，需要同时知道请求的 CLOS 和请求所用的 L3 分配域。即使线程留在原来的控制组，迁移到另一个 L3 域也可能换用该组的另一份掩码。

在同一组里复算独占与重叠 ​

沿用共享缓存一节的题设。A0、A1、A2、B0、B1、B2 是六个不同的物理块，恰好进入同一个四路组。进入本节时，A 已经按 A0、A1、A2 读过一轮，分别放在路 0、1、2，路 3 为空。本节都用精确 LRU。要填充时先从允许的路中找空位，允许的位置均已占满才替换其中最久未使用的一路。真实处理器的替换算法和填充条件需由其实现决定。

给 A 掩码 0111、B 掩码 1000。最右边是第 0 位，B 唯一能用的是路 3。B0 填入该路，B1 替掉 B0，B2 又替掉 B1。A 的三个旧块都保留，下一轮全命中。作为基线，如果双方都是 1111，B 可使用整个组，按上一节的顺序，A 下一轮三次都未命中。

只改一个条件，把 B 的掩码从 1000 改成 1100。此时 A 与 B 都能在路 2 填充，因为 0111 & 1100 = 0100。

LLC 请求命中或替换路 0、1、2、3 的内容
初态A 已先读一轮A0、A1、A2、空
B0未命中，填入空路 3A0、A1、A2、B0
B1未命中，路 2 的 A2 比 B0 更早使用A0、A1、B1、B0
B2未命中，路 3 的 B0 比 B1 更早使用A0、A1、B1、B2
A0、A1两次命中，更新路 0、1 的使用时间A0、A1、B1、B2
A2未命中，在路 0、1、2 中替换 B1A0、A1、A2、B2

A 只丢了 A2，B 也丢了原本驻留于重叠路的 B1。控制组在这一位上共用的是填充位置。加大 B 的可分配范围可以减轻 B 的自身替换，却可能重新引入这一路上的相互替换。

换了掩码，旧块为什么还能命中 ​

另设初态。A 原来可用四路，A0 已在路 3。现在将 A 移到掩码为 0111 的组，B 仍只允许在路 3 填充。按 Linux resctrl 文档，换组改变后续分配，已有行无需立即驱逐。

  1. A 首先读 A0。若旧块仍有效，这次在路 3 命中，不需要分配。
  2. B 读一个尚未驻留的 B0。它只能填路 3，于是替换 A0。
  3. A 再读 A0。现在查找未命中，必须重新填充，位置只从路 0、1、2 选择。

第 1 步与第 3 步使用的是同一份新掩码。结果不同，原因在于第 1 步已有有效块，而第 3 步需要为新块找位置。相同道理也适用于进程间共用的物理页。只要访问权限允许，另一个组的任务可以命中已存在的同一物理块。CAT 控制分配位置，读写权限仍由地址翻译所用的权限检查等机制决定。

用代码复算四个槽位 ​

下面是完整的 Python 3 教学模型。initial 按路号列出初态，题中初始有效行也恰好按路号从旧到新排列。requests 每项包含被读块和此次生效的掩码。输出逐项列出结果、路号和被替换的块。查找先检查已有行，只有未命中才使用掩码。

python
def simulate(initial, requests):
    lines = list(initial)
    last_used = [-4, -3, -2, -1]
    events = []

    for time, (block, mask) in enumerate(requests):
        if block in lines:
            way = lines.index(block)
            event = (block, "hit", way, None)
        else:
            allowed = [way for way in range(4) if mask & (1 << way)]
            way = min(allowed, key=lambda i: (lines[i] is not None, last_used[i]))
            event = (block, "miss", way, lines[way])
            lines[way] = block
        last_used[way] = time
        events.append(event)

    return events


warm_a = ["A0", "A1", "A2", None]
for a_mask, b_mask, expected in [
    (0b1111, 0b1111, ["miss", "miss", "miss"]),
    (0b0111, 0b1000, ["hit", "hit", "hit"]),
    (0b0111, 0b1100, ["hit", "hit", "miss"]),
]:
    sequence = [(block, b_mask) for block in ("B0", "B1", "B2")]
    sequence += [(block, a_mask) for block in ("A0", "A1", "A2")]
    events = simulate(warm_a, sequence)
    assert [event[1] for event in events[3:]] == expected
    print(f"A={a_mask:04b} B={b_mask:04b}", events)

moved = simulate(
    [None, None, None, "A0"],
    [("A0", 0b0111), ("B0", 0b1000), ("A0", 0b0111)],
)
assert moved == [
    ("A0", "hit", 3, None), ("B0", "miss", 3, "A0"), ("A0", "miss", 0, None),
]
print("Moved:", moved)

练习：A 独占三路以后，工作集也变大了

B 完全停下。A 沿用 0111，在同一个组循环读 A0、A1、A2、A3。第一轮结束后，下一轮能命中几次？

零次。A3 填充时挤掉最早的 A0。下一轮读 A0 时，它又会替换 A1，后续依次发生同样的替换。路 3 即使空着，也不在 A 的可选范围内。若 A 改回四路，四个块可以在第一轮后同时留下。

从 Linux 的配置查到这次生效的掩码 ​

图 1 来自 Intel 的 ExCat 项目文档。每个外框是一个处理器插槽。图中 CPU 0、CPU 2 分属两个 L2，却共用下面的 L3。CPU 4 在另一个插槽，有另一份 L3 分配设置。原图的 C1、C2 是项目示例的两类设置，分别示意 L2、L3 划出的区域。下方的 A、B 则沿用本文的四路题设。

假设有两个四路 L3 分配域，编号为 0 和 1，都允许单独分配一路。CPU 0、CPU 2 在域 0，CPU 4 在域 1。下面是题设机器上读到的三份 schemata 的内容，分号隔开同一资源的两个分配域。

再假设线程 4101 在 A 组的 tasks 中，CPU 0 在 B 组的 cpus_list 中，CPU 2 未分配给其他组。Linux v6.12 对控制组的选择顺序是非根任务组、CPU 所属组、根组。把这个顺序和分配域一起应用，就能算出一笔填充使用哪份配置。

运行情况控制组结果
线程 4101 在 CPU 0 运行A，线程所属组优先域 0 用 7，可在路 0、1、2 分配
根组线程在 CPU 0 运行B，采用 CPU 所属组域 0 用 8，可在路 3 分配
根组线程在 CPU 2 运行根组域 0 用 f，可在任一路分配
线程 4101 迁移到 CPU 4仍是 A域 1 用 f，可在任一路分配

所以这三份配置只能说明 A 和 B 在域 0 的新分配互不重叠。根组仍可填满四路，域 1 的 A 与 B 也仍有交集。读已有配置时，先确定任务在哪个 CPU 和缓存域上，再查看控制组与掩码，最后核对其他使用者。现场能读取的主要文件如下。

文件解读时要看什么
info/L3/cbm_mask、min_cbm_bits全部可用位及最小置位约束，决定题中的单路掩码是否合法
tasks、cpus_list组包含哪些任务或逻辑 CPU，和运行位置结合才能选出有效组
schemata各缓存分配域的掩码。L3:0=7 中的 0 是域编号
info/L3/bit_usage、shareable_bits检查其他使用组和可与设备共享的位
mon_data/mon_L3_00/llc_occupancy适用配置下，该监控组在域 0 的当前占用快照

掩码连续性的限制随硬件而异。配置独占组时，resctrl 还会检查其他控制组的掩码。上面的根组覆盖域 0 的全部位置，即使 A 与 B 互不重叠，也不能直接把 A 标为独占组。需要确认各组和相关硬件使用者的配置，才能把两组例题推广到实际部署。

占用量和新分配范围要分别看 ​

CLOS 选择分配配置，RMID（Resource Monitoring ID，资源监测编号）用于汇总监测事件。把线程从一组迁到另一组以前，旧组可能已经积累了缓存占用。迁组后立刻查看两个组，旧组的占用可以暂时保留，新组则要等新的缓存行被计入。命中原先缓存的行并不会把旧占用自动转记到新监控组。对照前面的旧行命中，第 1 步可以读到 A0，第 3 步才有一次使用新掩码的分配。

占用快照可以说明某一监控组在某一缓存域还保有多少数据。若要评价分区是否减少了相互替换，还需用固定工作量比较 LLC 请求和未命中，写明运行在哪个域、哪些组同时活动、何时开始计数。若两组已减少 LLC 替换，却仍共用 DRAM 控制器，未命中返回可能继续排队。DRAM 行调度的例题给出了两次未命中数量相同而完成时刻不同的情形。
