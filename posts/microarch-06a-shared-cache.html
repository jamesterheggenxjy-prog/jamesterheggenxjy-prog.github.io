两个核心只读各自的数组，地址没有重叠。单独运行时，两个程序都能在缓存中反复使用自己的数据。一起运行时，有些本来会命中的读取却要向更下一级请求。分析这种争用，需要找出两条数据访问路径在哪一级汇合，再追踪那里发生的替换。

先修知识是组相联缓存的地址映射和组内替换。本文只研究两个只读工作负载，关注各自的访问怎样改变另一方的数据驻留。

  • 从两个只有自己能用的缓存走到共享缓存

  • 少一次 LLC 命中会从哪里看到

从两个只有自己能用的缓存走到共享缓存 ​

考虑两个核心，各有私有 L1 和 L2。它们向同一个末级缓存（LLC）发请求。LLC 是这条普通请求路径上离核心最远的一层缓存。遇到 L1 或 L2 命中，数据可就地返回，未必需要向 LLC 查找。私有层都未能提供数据时，才轮到 LLC 判断是否能提供所需块。题设采用如下路径：

text
核心 A → A 的 L1 / L2 ─┐
                      ├→ 同一个 LLC → 下一级
核心 B → B 的 L1 / L2 ─┘
1
2
3

末级缓存的共享范围随平台而异。同一个处理器封装内可以有多个缓存实例，不同逻辑 CPU 也可能共用更近的一层。Linux 用缓存实例 ID 描述这样的共享范围。比如某台题设机器中，CPU 0 和 CPU 2 的 L3 ID 同为 0，CPU 4 的 L3 ID 为 1。把两项工作分别放在 CPU 0 和 CPU 2，才可以用上图中的同一个 LLC 来解释；若其中一个移到 CPU 4，就要用两个实例重新画出请求路径。在 Linux 上核对这种情况，可以查看对应 CPU 的缓存信息，先认清 level 与 type，再对照这一层的 id 和 shared_cpu_list。CPU 编号的大小关系本身说明不了共享范围。

一组四路，两个各用三块的程序 ​

只看共享 LLC 的一个组。它有四路，采用精确 LRU。A 的三个块叫 A0、A1、A2，B 的三个块叫 B0、B1、B2。六块是不同物理块，题设规定它们都进入这一组。表中只列到达 LLC 的请求，省去私有缓存已解决的读取，也不计预取、写回或其他核的访问。

A 先按 A0、A1、A2 读取一轮，三个块已在 LLC。若此后只重复 A 的序列，三个块可以留在四路里，下一轮有三次命中。现在让 B 在 A 的两轮之间依次读 B0、B1、B2。组内顺序从最久未使用排到最近使用。

到达 LLC 的操作此次结果被替换的块本组访问后的顺序
A 完成第一轮三块已填入无A0、A1、A2
B 读 B0未命中无，有空路A0、A1、A2、B0
B 读 B1未命中A0A1、A2、B0、B1
B 读 B2未命中A1A2、B0、B1、B2
A 读 A0未命中A2B0、B1、B2、A0
A 读 A1未命中B0B1、B2、A0、A1
A 读 A2未命中B1B2、A0、A1、A2

B 停止读取时，A2 其实还在。A 的第一笔重新填充 A0 又驱逐了 A2，所以后来访问 A2 同样未命中。总影响由整段访问顺序决定，仅数 B 直接驱逐了几个块，会漏掉后续替换的连锁影响。

如果给两个任务不同的填充范围，先在组内缩小每次可选的路，再沿同一条访问顺序重算。CAT 的四路例题用刚才的 A0 至 B2 演示两组分配范围完全分开和只重叠一路时的结果。

这里的共享发生在同一个组的可用路。A、B 没有交换所读数据的所有权。伪共享则是两个访问落在同一个物理块，写权因一致性协议来回交接。这两个过程都可能增加等待。阅读实验时先核对它讨论的是同一块上的权限交接，还是不同块之间的替换。

少一次 LLC 命中会从哪里看到 ​

表中 A 的三个请求已到达 LLC，因此最后三次查找都要进入其未命中处理。实际完整程序若仍能在私有 L2 找到 A2，那么这一笔不会走到表中的最后一行。还要知道 LLC 替换是否会影响私有缓存的副本。比如 Intel 对第一代 Xeon Scalable 的说明指出，该系列改用了非包含式 LLC，私有层与 LLC 的数据放置不同于之前的包含式设计。拿到真实机器的指标时，应分别查私有层命中、LLC 请求和下级流量，再用型号文档解释三者的关系。

复查一组变慢的结果时，可以从一个正常服务的固定工作量出发，同时比较独占运行与混合运行的 LLC 请求数和未命中数。若未命中数改变，再结合返回来源和实际工作量确认替换影响。若未命中数保持近似相同，还要检查同一个下级接口是否开始排队。下一篇将固定未命中次数，仅改变到达同一服务端的其他请求。

练习：B 只访问 B0

仍在 A 已经读过 A0、A1、A2 后运行 B。把 B 的序列改成只反复读取 B0。A 的下一轮访问要发生几次 LLC 未命中？

B0 第一次填进空路，以后的同块访问可以命中。A 的三个块依旧留在组内，下一轮有零次未命中。这个结果和 B 进行了多少次读取没有直接关系。需要看这些读取实际占了几路，以及新块到来时有没有可用的位置。
