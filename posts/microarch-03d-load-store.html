加载与存储单元的结构 ​

加载／存储单元（Load/Store Unit，LSU）一端接执行流水线，另一端接数据缓存。加载和存储进入执行后端时，先在相应队列里留位置。等基址寄存器就绪，执行单元计算有效地址并送入 LSU。TLB 提供地址翻译所需的信息，LSU 才能用物理地址比较两条访问是否指向同一处。存储的源数据由另一个寄存器提供，可以独立到达。

图 1 上方，STQ 是存储队列（Store Queue），LDQ 是加载队列（Load Queue）。左侧比较逻辑 Searcher 从两类队列读取地址和状态。它既可以在加载时搜索在先的存储，也可以在存储地址得到翻译后，检查在后的加载是否已经沿错误的依赖关系执行。图右的 Data Cache 是另一条取数路径。缓存命中时，数据阵列直接返回数据。未命中时，由缓存的 MSHR 跟踪缺失的缓存行。转发的数据和缓存返回的数据最终都接到图底部的选择器。

队列项里存着什么 ​

图中用 addr、data 等短标签指示字段。下面列出本节会用到的 BOOM v3 状态。

位置字段或状态在什么情况下改变
STQ表项有效、addr.valid、addr_is_virtual分配时先占用表项。计算出虚拟地址后可暂存，翻译成功后才能用物理地址做最终比较
STQdata.valid、data存储的源寄存器值送达后置有效，地址和数据可以分开就绪
STQcommitted、succeededROB 退休存储时标记已提交，收到缓存完成确认后再标记已完成
LDQaddr、addr_is_virtual、st_dep_mask记录加载的地址与翻译状态。掩码的每一位对应一个可能依赖的较老 STQ 项
LDQexecuted、succeeded分别记录向内存侧执行的进度和是否已经取值成功。请求被拒绝可以使加载重新进入等待
LDQforward_std_val、forward_stq_idx、order_fail保留转发来源的索引和顺序检查结果，供后续检查

st_dep_mask 表示哪些较老存储仍需要考虑。某一位为 1 时，队列项可能连地址都没有。真正是否依赖，还要等地址和访问大小参与比较。相应的存储项完成、退出队列后，它对应的掩码位会清除。

一次完整的存储转发 ​

假设一个 RV64 线程修改自己的计数值。x10 和 x13 都指向 0x1000，该位置八字节对齐、可缓存，翻译和权限检查都能通过。L1 初始保存 5，x11 保存准备写入的新值 9。

asm
sd   x11, 0(x10)    # S：向 0x1000 写入 8 字节
ld   x12, 0(x13)    # L：从 0x1000 读取 8 字节
addi x14, x12, 1    # I：使用 L 的结果

sd 需要两份输入。x10 + 0 给出地址，x11 给出数据。如果 x11 先就绪，存储的数据操作就先填 STQ.data，其地址子操作仍可留在发射窗口。若两个操作数都已就绪，BOOM 可以用一次发射把地址和数据一起送进 LSU。ld 只用基址计算地址，取回的数据再写入为 x12 分配的物理寄存器。

示例周期队列和流水线中的动作这时能确定的结果
4S 的数据送到 STQ，data.valid 置位队列里已有 9，尚不知要写到哪里
6S 的地址生成并完成翻译可以确定 S 覆盖的物理字节，S 尚未退休
8L 的地址到达比较逻辑，命中 S 的全部八字节取消 L 对 L1 的尝试，从 S 转发 9
9I 消费 L 已写回的值I 在内部算出 10
12S 到达 ROB 队头并退休STQ 项标为已提交，可以按顺序向缓存发送
14本例假定缓存接下 S 的写入L1 中该位置更新为 9

这些周期是题设。第 8 周期的关键在于，缓存仍保留 5 时，转发已经能让同一线程的 L 得到 9。STQ 项的提交标志决定何时允许这笔写入向缓存发送。其他核心何时能观察到写入，还要看一致性协议和架构内存模型。

如果只把 S 的数据就绪时间从第 4 周期挪到第 10 周期，第 8 周期仍能确定地址重叠。L 因为拿不到 9 而等待，之后重试。如果改的是 x13，让 L 读取 0x1008，S 写到 0x1007 为止，两次访问可以落在同一条缓存行上，却没有共享字节。此时 L 可以继续走缓存取数路径。

怎样判断字节重叠和转发来源 ​

比较地址需要回答两件事。访问范围有没有重叠？存储覆盖了加载需要的全部字节吗？BOOM v3 对本节这类普通对齐访问先比较物理地址所属的八字节单元，再由地址低位和访问大小生成字节掩码。掩码第 0 位对应这个单元的最低地址。设读掩码为 R、写掩码为 W，那么 R & W != 0 表示重叠，R & W == R 表示全覆盖。

以小端存储 0x1122334455667788 为例。地址 0x1000 开始的八个字节依次为 88 77 66 55 44 33 22 11。lwu 从 0x1004 取四字节并零扩展。因此，即使两条指令的起始地址不同，sd 的 0xff 仍完整覆盖 lwu 的 0xf0，可以转发 0x11223344。若存储改为从 0x1004 开始写两字节的 sh，写掩码为 0x30，只能覆盖读掩码 0xf0 的一部分。此时 BOOM v3 的这条转发路径会阻止加载继续取缓存旧值，等重试条件成立后再取数。这里讨论的是单项转发，整个加载最终仍要得到每个字节应有的值。

如果在例题的 S 之前再插入一条往 0x1000 写 7 的存储 S0，会有两个匹配项。BOOM v3 先根据程序顺序选出在 L 之前最接近 L 的匹配项 S，再确认它能否转发。即使 S0 的 7 早已备好，只要 S 覆盖同一个位置，L 就必须等 S 的 9。若先用就绪与否筛选来源，就会绕过程序中那次实际应生效的写入。

用代码检查选择顺序 ​

下面的 Python 代码只处理上面已经确定物理地址的例题。列表中的元素代表还在队列里、并且比该加载更早的存储，按程序顺序排列。代码先从较新的项找重叠，再判断全覆盖和数据就绪。缓存数据由两个八字节值组成，偏移 0 和 8 分别对应地址 0x1000 和 0x1008。

python
def read_from_queue(cache, stores, offset, size):
    read_end = offset + size
    for start, width, value in reversed(stores):
        write_end = start + width
        if write_end <= offset or read_end <= start:
            continue
        if start > offset or write_end < read_end or value is None:
            return "wait", None

        data = value.to_bytes(width, "little")
        start_in_data = offset - start
        return "forward", int.from_bytes(
            data[start_in_data : start_in_data + size], "little"
        )

    return "cache", int.from_bytes(cache[offset:read_end], "little")


cache = (5).to_bytes(8, "little") + (13).to_bytes(8, "little")
s0 = (0, 8, 7)
s = (0, 8, 9)
wait_for_s = (0, 8, None)
wide = (0, 8, 0x1122334455667788)
half = (4, 2, 0xABCD)

assert read_from_queue(cache, [s0, s], 0, 8) == ("forward", 9)
assert read_from_queue(cache, [s0, wait_for_s], 0, 8) == ("wait", None)
assert read_from_queue(cache, [s], 8, 8) == ("cache", 13)
assert read_from_queue(cache, [wide], 4, 4) == ("forward", 0x11223344)
assert read_from_queue(cache, [wide, half], 4, 4) == ("wait", None)

存储地址迟到，加载怎样重试 ​

回到第一段汇编，只把 S 的地址延后。假定第 8 周期 L 发出读请求时，STQ 里已经有 9，却还没有可用于比较的 S 地址。BOOM 可以先让 L 尝试访问缓存。若缓存返回旧值，检查就要等到 S 的物理地址出现。

示例周期已有记录下一步怎样处理
8LDQ 的相关存储掩码还含 S，S 的物理地址未就绪L 向 L1 发出尝试性的读请求
9L 已从缓存取得 5I 随后可能以 5 为输入算出 6
11S 的物理地址得到确认比较逻辑查到已经取值的 L 与 S 重叠，且 L 的 5 来自缓存，报告顺序失败
重试L 和依赖它的年轻结果需要恢复L 重新执行，取得 9，I 再算得 10

第 11 周期的检查方向和第 8 周期不同。年轻的 L 初次取值时搜索较老的 STQ 项。较老的 S 地址就绪后，BOOM v3 反过来搜索已经执行的相关 LDQ 项。如果 L 的值来自比 S 更早的存储，也必须检查这次更近的写入是否被跳过。源码中的 forward_stq_idx 就为这种检查保留了原始来源。顺序失败由核心内部处理，从需要重试的加载恢复执行，已经消费旧值的年轻结果也跟着撤销。这个例题没有权限错误，程序最终仍正常读到 9。

练习：把加载位置移到原存储的后一半

回到完整转发的时间线，把 S 的数据换为 0x1122334455667788，把 L 改成从 0x1004 开始的 lwu。第 8 周期应从哪里取数？把 S 改成从 0x1000 开始的四字节 sw，其余保持不变，再判定一次。

第一次，读掩码是 0xf0，写掩码为 0xff，应从 S 取其高四字节，即 0x11223344。第二次，sw 的写掩码变成 0x0f，与 0xf0 没有交集，L 走缓存路径。两种访问都在同一个八字节单元里，区别由字节掩码给出。
