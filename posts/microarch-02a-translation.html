发布于 1970/01/01 | 约0字

程序执行一条 RISC-V 的 lw a0, 0(a1)。令 a1 = 0x404035e8，这条指令要在当前地址空间中读四个字节。对程序可见的是这个虚拟地址。存储系统还需要目标物理地址和访问许可，才能决定从哪里取数据。下面使用 Sv39 把这一步算完，随后重复同一条加载，观察结果怎样被缓存，以及页表更新后怎样让新翻译生效。

例题为 RISC-V U 模式的单阶段翻译，数据按小端解释。地址、表项内容和读到的值由题设给定。字段和权限依据 RISC-V 特权规范 v20250508，硬件接口以公开的 CVA6 MMU 为例。先修知识是缓存怎样用地址选组和行内字节。

加载单元向 MMU 交出什么 ​

MMU（Memory Management Unit，内存管理单元）连接取指和访存路径。图 1 中，LSU（Load/Store Unit，加载与存储单元）送入虚拟地址、读取或写入的类型及特权状态。控制寄存器端提供根表的物理页号、地址空间标识及权限相关配置。数据侧的 MMU 结果包括是否命中 DTLB、翻译后的物理地址、有效状态和异常信息。读图时先沿左侧的 lsu_vaddr_i、satp_ppn_i，再找到右侧的 lsu_paddr_o 和 lsu_exception_o。

MMU 内部的 TLB（Translation Lookaside Buffer，翻译后备缓冲）保存已有的翻译。取指路径可查 ITLB，数据访问可查 DTLB，另可配置共享 TLB。需要重新查页表时，由 PTW（Page Table Walker，页表遍历器）根据根表和虚拟页号发出读表请求。在 CVA6 的设计文档中，PTW 的读取走数据缓存侧接口。一次原始加载由此可能带出额外的物理访存，用来读取页表项。它们与最后那笔程序数据的读取具有不同地址。

从 64 位虚拟地址拆出三个索引 ​

在 Sv39 中，普通页长 4 KiB，即 4096 字节。低 12 位决定页内偏移，另外三个 9 位字段是虚拟页号 VPN 的三段。64 位虚拟地址的位 63 至 39 必须与位 38 相同，否则不能按合法的 Sv39 地址继续翻译。这条加载地址的位 38 和更高位均为 0。

字段位范围对 0x404035e8 的值
VPN[2]38–301
VPN[1]29–212
VPN[0]20–123
页内偏移11–00x5e8

先取低 12 位得到 0x5e8。除去它，再从低到高每次取 9 位，依次得到 3、2、1。普通页映射只替换页号。哪怕新的物理页与原物理页相距很远，仍要在新页中取同一个偏移。

三级页表怎样给出物理页号 ​

每级页表有 512 项，一项 PTE（Page Table Entry，页表项）占 8 字节，一整张表恰好占 4 KiB。当前表的物理基址加上该级索引乘 8，就是要读的表项地址。根表由监管者寄存器 satp 指定。在 RV64 的 Sv39 模式下，MODE = 8，ASID 用于区分地址空间，PPN 给出根表的物理页号。本例的 ASID = 7，根表 PPN 为 0x90，因而从 0x90000 开始。物理表项里再给出下一级的 PPN。有了这些物理地址，遍历就无需为自己读取的 PTE 递归做同一套虚拟翻译。

级别当前表基址索引PTE 的物理地址从内存读到的 PTE含义
2，根表0x9000010x900080x25001仅 V 置位，下一级 PPN 为 0x94
1，中间表0x9400020x940100x26001仅 V 置位，下一级 PPN 为 0x98
0，末级表0x9800030x980180x48c53叶子，目标 PPN 为 0x123

结合位域读一项。PTE 的位 53 至 10 是 44 位 PPN，位 9 至 8 的 RSW 留给监管者软件。位 7 至 0 依次是 D、A、G、U、X、W、R、V。本例未启用使用高位保留字段的扩展，高位清零。V 为 0 或 R 为 0 而 W 为 1 时，本例按页错误处理。有效的项若 R 或 X 置位，就是给出映射的叶子项。R、W、X 都为 0 时，用 PPN 进入下一级。普通非叶子项的 U、A、D 位保留，软件应清零。若已到第 0 级却还是指针，遍历也会失败。

0x98018 是存放叶子项的地址。从此处读到 0x48c53，右移 10 位得到 0x123，低位 0x53 表示 V、R、U、A 均置位。页起点 0x123000 加上偏移 0x5e8，得到数据的物理地址 0x1235e8。若行长为 64 字节，数据缓存要找到的行起点是 0x1235c0，再读偏移 0x28 至 0x2b。题设给该位置的四字节为 25 00 00 00，加载得到 37。

哪些条件会使同一地址报错 ​

用同一个叶子试三种变化。第一种把加载改为存储，W 为 0，会产生 Store/AMO page fault。第二种只把 U 清零，U 模式的加载也会产生页错误，即使物理页号和值都没改。第三种保留页权限，却遇到物理内存保护（PMP）或物理地址区域属性（PMA）的拒绝，可能得到访问错误。读异常记录时，要分清是虚拟地址翻译的权限，还是物理访问本身不允许。若程序在一个可读页中只分配了长度较小的数组，页的 R、U 位仍覆盖整页，具体数组边界需要由程序处理。

A、D 分别表示已访问和已写。主例 A 已置位，读操作无需修改表项。若 A 为 0，或者写请求发现 D 为 0，体系结构允许按所采用的机制处理。使用 Svade 机制时会产生页错误，由软件处理。采用硬件更新机制时，处理器依规定更新 PTE。硬件更新方案允许 A 因投机访问而提前更新，即使该次访问最终没有成为架构上的访存。显式存储引起的 D 位更新必须是非投机的，并由本 hart 按程序顺序观察。因此看见 A 置位，不能倒推出某条加载一定已经退休。

先在中间一级遇到叶子 ​

若 0x94010 里的项改成叶子，遍历在级别 1 结束，映射页长变为 2 MiB。VA 的 VPN[0] 与低 12 位一起构成 21 位页内偏移。本例的偏移是 (3 << 12) + 0x5e8 = 0x35e8。若物理基址取 0x60000000，结果就是 0x600035e8。此时 PPN 的低 9 位要为零。若改用 0x60001000 作为大页基址，表项虽然仍是叶子，却因未对齐而报页错误。根表本身也可放叶子，得到 1 GiB 的映射，需要保留原 VA 的低 30 位，物理基址相应按 1 GiB 对齐。

练习｜相邻两字节的物理地址一定相邻吗

设 0x40403fff 的虚拟页仍映到物理页 0x123，紧接着的 0x40404000 映到物理页 0x565。两个地址在物理侧分别是多少？

第一个为 0x123fff，第二个为 0x565000。虚拟地址刚跨页，物理页可能相距很远。硬件预取遇到虚拟候选跨页时，也要根据实现决定重新翻译还是丢弃候选。

TLB 命中后还要检查什么 ​

第二次访问同一个地址时，MMU 可以复用上一笔得到的翻译。图 3 展示了 CVA6 的一种实际 TLB 表项。Tag 一侧有 ASID、VPN、适用页级和表项有效位。Content 一侧有物理页号与 PTE 权限。图中的 VMID 和阶段使能字段还服务于虚拟化，本文只使用单阶段配置。TLB 自己的 VALID 控制该槽是否有效，内容里的 V 是从 PTE 得到的位。

对于主例的非全局 4 KiB 页，匹配键可写成 (ASID 7, VPN 0x40403)。命中时直接得到 PPN 0x123 和权限字段。仍要检查这次操作是读还是写、当前特权模式是否允许，然后拼出物理地址。对 2 MiB 项，低 9 位 VPN 已成为页内偏移的一部分，比较时使用更高的页号前缀。全局标记 G 可以放在遍历路径上的项中，表示该翻译适用于所有地址空间。在支持 ASID 的实现中，普通项需要匹配 ASID，全局项按不同规则处理。

若同一个 hart 换到 ASID 8，地址依然是 0x404035e8，它可以有另一个根表并映到 0x7775e8。ASID 7 的表项不应用于它。另一方面，即使 DTLB 未命中，也可能由共享 TLB 或缓存的中间遍历结果提供帮助。DTLB 未命中、完整读取三项 PTE、数据缓存未命中分别涉及不同结构。读性能计数时，应确认计数的是哪一步。

改完页表，为什么还要同步翻译 ​

设管理程序将 ASID 7 的末级项从 PPN 0x123 改成 0x567，读权限保持不变。若之后完整遍历，会从 0x98018 得到新 PPN。但旧翻译可能仍在 TLB 或其他地址翻译缓存里。有了旧项的命中，本次访问不一定重新读取那份 PTE。不同实现和时机下，旧项也可能已经被换出。软件不能用“我已经写了页表”推断下一笔访问必然按新映射进行。

RISC-V 用 SFENCE.VMA 对本地硬件线程（hart）同步地址翻译和页表更新。它让本 hart 已可见的页表写入，和作用域内之后的隐式页表访问有规定的顺序，并处理相关的旧翻译。两项源寄存器的选择决定范围。

rs1rs2最小规定作用域
x0x0所有地址空间、各级页表与翻译
x0持有 ASID 的非 x0 寄存器此 ASID 的各级翻译，排除全局映射
持有页内虚拟地址的非 x0 寄存器x0所有地址空间内覆盖该地址的叶子映射
持有页内虚拟地址的非 x0 寄存器持有 ASID 的非 x0 寄存器此 ASID 中覆盖该地址的非全局叶子映射

“寄存器是 x0”和“某个非 x0 寄存器里数值为 0”含义不同。后者作为 rs2 时选择 ASID 0。具体实现允许清除比表中更多的项。修改非叶子指针时要考虑整棵子树，规范建议用 rs1 = x0。若路径上有全局标记，处理相关映射时要用包含全局项的范围。写 satp 本身没有自动清掉所有翻译的保证，回收 ASID 时也要把它与旧根表关联的翻译同步掉。

两个 hart 都可能使用旧映射时，只在修改者所在的 hart 同步还不够。操作系统先保证新的页表内容对目标 hart 可见，再让目标 hart 完成当地的翻译同步并回报完成。这个过程常称 TLB shootdown。例如系统准备回收此前映射的物理页时，就要把仍可能使用旧翻译的 hart 纳入这次同步。数据缓存里有没有那条物理行，是另一个状态。

复算同一个地址的四种结果 ​

下面是单 hart 教学模型。内存表以 PTE 物理地址为键。TLB 只缓存非全局映射。访问先以 ASID 和页前缀查缓存，仍用叶子标志判断 U 模式的读写许可。采用 Svade 式的 A/D 检查，省略实际数据缓存、MXR 与 PMP。代码中的失效只模拟题设指定范围，未执行处理器指令。存为 sv39_walk.py，用 Python 3 运行 python sv39_walk.py。

python
V, R, W, X, U, G, A, D = (1 << bit for bit in range(8))
VA = 0x404035E8
LEAF = 0x98018
USER_READ = V | R | U | A
ROOTS = {7: 0x90000, 8: 0xA0000}
DATA = {0x1235E8: 37, 0x5675E8: 52, 0x7775E8: 81}


class PageFault(Exception):
    pass


def encode(ppn, flags):
    return (ppn << 10) | flags


def walk(memory, table, va):
    visited = []
    for level in (2, 1, 0):
        shift = 12 + 9 * level
        index = (va >> shift) & 0x1FF
        pte_address = table + index * 8
        visited.append(pte_address)
        pte = memory.get(pte_address, 0)
        if (pte >> 54) or not (pte & V) or (pte & W and not (pte & R)):
            raise PageFault("invalid PTE")
        if pte & G:
            raise NotImplementedError("global mapping")
        if pte & (R | X):
            if ((pte >> 10) << 12) & ((1 << shift) - 1):
                raise PageFault("misaligned superpage")
            return pte, shift, tuple(visited)
        if pte & (U | A | D):
            raise PageFault("reserved bits in non-leaf PTE")
        table = (pte >> 10) << 12
    raise PageFault("no leaf")


def physical_address(pte, shift, va, store):
    if not (pte & U) or not (pte & (W if store else R)):
        raise PageFault("U permission")
    if not (pte & A) or (store and not (pte & D)):
        raise PageFault("A/D")
    return ((pte >> 10) << 12) | (va & ((1 << shift) - 1))


class MMU:
    def __init__(self, memory):
        self.memory = memory
        self.tlb = {}

    def translate(self, va, asid, store=False):
        upper = ((1 << 25) - 1) if va & (1 << 38) else 0
        if not (0 <= va < 1 << 64) or (va >> 39) != upper:
            raise PageFault("invalid virtual address")
        for (entry_asid, page, shift), pte in self.tlb.items():
            if entry_asid == asid and va >> shift == page:
                return physical_address(pte, shift, va, store), ()
        pte, shift, visited = walk(self.memory, ROOTS[asid], va)
        pa = physical_address(pte, shift, va, store)
        self.tlb[asid, va >> shift, shift] = pte
        return pa, visited

    def invalidate_leaf(self, va, asid):
        matching = [
            key for key in self.tlb
            if key[0] == asid and key[1] == va >> key[2]
        ]
        for key in matching:
            del self.tlb[key]


def make_memory():
    return {
        0x90008: encode(0x94, V),
        0x94010: encode(0x98, V),
        LEAF: encode(0x123, USER_READ),
        0xA0008: encode(0xA4, V),
        0xA4010: encode(0xA8, V),
        0xA8018: encode(0x777, USER_READ),
    }


def load(mmu, asid):
    pa, entries = mmu.translate(VA, asid)
    if entries:
        print("walk", hex(pa), DATA[pa], "via", *(hex(p) for p in entries))
    else:
        print("hit", hex(pa), DATA[pa])


if __name__ == "__main__":
    mmu = MMU(make_memory())
    load(mmu, 7)
    load(mmu, 7)
    load(mmu, 8)
    mmu.memory[LEAF] = encode(0x567, USER_READ)
    load(mmu, 7)
    mmu.invalidate_leaf(VA, 7)
    load(mmu, 7)
    load(mmu, 8)
    mmu.memory[LEAF] = encode(0x567, V | R | A)
    mmu.invalidate_leaf(VA, 7)
    try:
        load(mmu, 7)
    except PageFault as fault:
        print("fault", fault)

前两行对应首次遍历和命中。第三行地址相同、ASID 不同，因而走另一张页表。修改后未同步的第四行，模型故意保留旧项，展示规范允许出现的一种结果。第五行失效后重走页表，保持原偏移，读到新物理页里的 52。第六行的 ASID 8 仍可命中，这是本模型按指定范围失效的结果。最后清掉 U，即使物理地址的页号没变，同步后也只能得到页错误。判断三次变化时，应分别核对地址、权限和查找所用的旧记录。
